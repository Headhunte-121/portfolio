"I kept losing my place across anime and lecture backlogs without wanting a heavy 24/7 media server (Plex/Jellyfin), so I designed and directed the build of a zero-daemon local tracker."

A fast, native desktop media diary and VLC companion for Windows, built using an AI-augmented development workflow. Connects to VLC via loopback HTTP to track viewing history and timestamps with zero background daemons, 0.0% idle CPU, and a tiny 15.1 MB RAM footprint across 6 decoupled subsystems:

Custom Streaming Protocol (watchmark://)

Native async URI scheme implementing HTTP Range header parsing and 1MB chunked streaming to bypass WebView2 local sandbox constraints without RAM bloat.

Multi-Threaded Ingestion & Triage

Recursive walkdir scanner parsing release tags (clean_anime_release_tags, x264, 1080p), Windows long paths (\\?\), and Win32 handle IDs into an interactive triage inbox.

Zero-Daemon VLC Telemetry

Tokio async supervisor with dynamic port probing (8080..8090), 16-char cryptographic auth, and >90% completion latching with 0.0% background CPU.

Dual-Channel MPSC Task Queue

Dedicated worker thread prioritizing UI operations over background sweeps (high_priority_tx / low_priority_tx), preventing SQLite concurrency deadlocks.

Transactional Cold-Swap Restore

SQLite WAL mode with PRAGMA optimize, 3-backup SHA-256 rolling retention, and transactional .pending → active database cold-swaps with automatic rollback.

03. WORKFLOW

How I Build With AI

AI tools work best when guided by clear architecture, small tasks, and strict verification. Here is the pragmatic 4-step workflow I use to go from idea to finished software without getting derailed by AI hallucinations.

STEP 01

Plan the Architecture & Break Down Features

Planning

Clear Specs First: AI models produce bad code when given vague, monolithic prompts. Before asking an AI to write code, I plan the system architecture, break down the features into modular pieces, and define clear boundaries between components.

In WatchMark

Broke down the 64-feature application into distinct modules (windowing, SQLite database, VLC telemetry, and frontend UI) so each part could be built and tested independently.

STEP 02

Manage AI Context & Keep It on Task

Execution

One Task at a Time: On large projects, AI models easily drift, lose context, or add unnecessary dependencies. I feed the AI small, focused tasks with clear constraints, keeping the context window clean and the codebase manageable.

In WatchMark

Guided the AI agent feature-by-feature against discrete milestones and GitHub issues, preventing code bloat across weeks of development.

STEP 03

Audit Scope & Verify Completion

Code Audit

Don't Trust the "I'm Done" Message: AI agents often cut corners—leaving placeholder comments, stubbed methods, or skipping error handling. I review the generated code to verify that what the AI claimed to build is actually implemented completely and correctly.

In WatchMark

When generating the custom video player, the AI reported the task "complete", but took a lazy shortcut: loading whole multi-gigabyte video files into RAM and leaving empty // TODO stubs for connection drops. Auditing the diff caught the shortcuts, enforcing true 1MB chunked Range streaming (bytes=start-end) and real error handling before merging.

STEP 04

Hands-On QA & Defect Hunting

Testing

Real-World Testing on Hardware: Code that compiles can still fail on real machines. Using my commercial QA testing experience, I test the live build on physical hardware to catch bugs, memory leaks, and performance problems that automated checks miss.

In WatchMark

Automated checks passed 100%, but testing the live build on physical hardware revealed the idle desktop window was burning 70.3% GPU in Windows Task Manager. Traced the leak in DevTools to an infinite CSS scale loop behind blurred glass and fixed it to 0.0% idle GPU. Also caught VLC resetting progress to 0.0 at the end credits, adding a ≥90% latch so completed episodes don't revert to unwatched.

Takeaway: Thoughtful Architecture • Focused AI Scaffolding • Rigorous Code Auditing • Hands-On Testing
